# Concierge

**[See what it does →](https://ylkhayat.github.io/concierge/)**

A dashboard on your own machine for AI coding agents. They review the PRs you're asked to look at, work through
feedback on your PRs, and ship your Linear tickets. You read and decide: nothing reaches GitHub or Linear until you
click.

It runs agents on **Claude** (Claude Code, with a claude.ai plan or an API key), **OpenAI** (Codex, with a ChatGPT
plan or an API key), **Copilot** (GitHub Copilot's CLI, on your Copilot plan) and **Llama** (local models through Ollama). Add as many accounts as you like, and Concierge
spreads the work across them.

## Install

```bash
gh repo clone ylkhayat/concierge && cd concierge
cp .env.example .env    # set CODE_DIR (the folder with your clones) and GITHUB_TOKEN
docker compose up -d
```

Open http://127.0.0.1:4747. A short setup signs you in to an agent and picks your repos (it can clone them for you).

On Docker Desktop, turn on host networking once first: Settings → Resources → Network → Enable host networking.

Without Docker, run `./install.sh` instead.

## What it does

- **Reviews.** When someone requests your review, an agent prepares it. You read the findings, then post or approve.
- **Your PRs.** One click works through the review comments. Another pushes and replies.
- **Explain.** Each PR is explained from two angles: what changes for users, and which parts of the code it touches. It builds on a map of the whole repo.
- **Ship.** A board of your Linear tickets. Pick tickets and agents ship them as PRs.
- **Plans, for product managers.** A brief broken down with an agent into epics and user stories (MoSCoW, RICE,
  acceptance criteria), drawn as one roadmap. Drag tickets earlier, onto another epic or into Later: every move is a
  scenario first, with when it lands, the appetite, the critical path and what finishes later, until Apply writes it,
  Linear included. One-click plays (fit the appetite, risk first, protect the date, balance owners), and readiness
  against your compliance profile (Settings → Compliance, filled from Linear and your code): what each plan must cover
  for GDPR, SOC 2 and the data you handle, whether the people building it can hold the work, and its risks.
- **Intent and Understanding.** Beside every PR and ticket, two discussions with an agent: one settles what the work is meant to do and ends in a decision record you agree on, the other walks you through the change from every angle Explain shows. What they settle reaches the agent when you send it.
- **Guard rails.** There is a limit on how many agents run at once and a daily budget ($20 by default). Agents only use the tools you allow. They never merge.

## Any number of machines

Concierge can run on as many machines as you have, all online at once. Every one of them runs agents, and one is the
main server your link opens. When it sleeps or goes offline, its standby takes over with every run and setting
intact, and hands back once the first is up to date. The machines keep in step themselves over your tailnet, as
changes, not a file sync. This is a private extension; ask the author for access.

**Adding a machine:** sign it in to the same Tailscale, clone this repo, run `bin/join --check` (it checks Docker, Tailscale, your policy and the main server without changing anything, and says how to fix what is missing), then `bin/join`. It finds Concierge on your
tailnet and asks to join. Signed in as the same person, it joins at once; anyone else waits for your approval in
Settings → Machines, with a code both screens show. It then sets itself up as the standby (or a worker beside one), and
your state, settings and sessions come over within a minute. Sign-ins stay per machine: Settings → Accounts signs it
in. Your Tailscale policy must let your devices reach `tag:concierge:4748`.

## Security

- **Your machine only, by default.** The dashboard listens on 127.0.0.1. A web page you visit can't make it act: requests
  a browser marks as coming from another site are refused.
- **Through your tailnet link, only the people you allow** (Settings → Machines → Who can open it): the first person to
  open it becomes its owner. If your link doesn't pass who is calling, or others share your tailnet, set
  `CONCIERGE_PASSWORD` in `.env` as well.
- **Someone else's PR is data, not instructions.** A review run gets only the secrets reviewing needs (GitHub's, and its
  own sign-in), can't read credential files or print its environment, and is told that nothing in the PR instructs it.
  It still holds your GitHub token, to read the PR and post the review you approve: use a fine-grained token limited to
  the repositories you watch, so that's all a misled run could touch.
- **Joining a machine shares your keys** with it (GitHub, Linear, the machine key). A device signed in to Tailscale as
  you joins without asking; anyone else waits for your approval.

## Make it yours

Most changes need no fork: your commands, skills, skill rules and code areas are settings
([reference](docs/reference.md)), kept outside the repo, so updates never touch them.

To change the code itself, fork it and point your clone at both repos:

```bash
gh repo fork ylkhayat/concierge --clone && cd concierge   # origin is your fork, upstream is this repo
```

`bin/update` (and the Update button) keeps updating from your fork, and only tells you when this repo has new
commits: Settings → Machines → Updates lists them, and an alert says so every few days. You choose when to take them:
**Merge and update** there (or `bin/update --upstream`) merges them into yours and pushes the result to your
fork, or set `CONCIERGE_UPSTREAM=merge` in `.env` to do that on every update. If they conflict with your changes,
nothing is touched and it says so: run `git merge upstream/main` and resolve the conflict. Fewer conflicts: keep your changes small and in their own files, and send the general ones back as a
pull request. Contributions are welcome.

### Its look

The whole design lives in two files. `src/design/tokens.css` holds every colour, text size, corner, shadow and motion
curve, for light and dark; `src/design/recipes.css` holds the few shapes built from them (buttons, cards, labels).
Change a value there and every screen follows. Components use only those names (`text-fg-2`, `bg-fill`, `text-ok-text`,
`rounded-card`, `btn-primary`); a test fails when a raw palette colour is added. `npm run dev`, then `/?gallery=design`
shows all of it on one page, live.

The native install, Docker details, configuration and development are in the [reference](docs/reference.md).
